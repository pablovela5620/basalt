Goal

Inside-out 6DoF tracking for an HP Windows Mixed Reality headset on Linux: Monado (OpenXR runtime, pure-pixi build) loads this repo's Basalt as a runtime SLAM plugin via the VIT 2.0 interface (libbasalt.so, dlopened through VIT_SYSTEM_LIBRARY_PATH — no build-time coupling), with live Rerun visualization of the tracking pipeline and an OpenXR client rendering to the headset.

Hardware findings (2026-07-05)

Headset core is unpowered. Evidence, despite "fully plugged in (USB + DP + power)":
  • Only the Cypress USB3 hub enumerates (04b4:6504, "HP Inc. HP Windows Mixed Reality", bus 2-7) — powered from USB bus voltage.
  • No 045e:0659 Microsoft HoloLens Sensors device (the cameras + IMU Monado needs).
  • Both downstream hub ports report not attached; hub is runtime-suspended.
  • The hub's USB2 companion device is absent from the 480M bus entirely.
  • All four GPU connectors (card1-DP-1/2/3, HDMI-A-1) report disconnected — no DP hotplug from the headset.
Interpretation: the hub chip is alive on USB power, but the internal rail feeding sensors, display and DP link is dead. Most likely: power brick unplugged / not delivering, loose barrel connector on the Y-cable, or a failing breakaway connection.

Physical checklist (user, when at the machine)

  1. Verify the headset's power adapter is in a live outlet and the barrel/breakaway connector on the Y-cable is fully seated.
  2. Unplug USB + power, wait 10 s, reconnect power first, then USB (headset-side connector too, if detachable).
  3. Confirm with lsusb -d 045e:0659 — the HoloLens Sensors device must appear.
  4. If still absent: try a different USB controller (the machine has several) and check the DP cable seats at the GPU.

Key technical facts

  • Basalt implements VIT 2.0 (thirdparty/vit/vit_interface.h); target basalt builds libbasalt.so including src/vit/vit_tracker.cpp.
  • Monado pinned at 4b339a28b — its src/external/vit_includes/vit/vit_interface.h is also 2.0.
  • Monado's euroc driver (drv_euroc) replays EuRoC-layout datasets through the full runtime — the headset-independent validation path.
  • Basalt ships VIT configs at data/vit/: msdmo.toml matches Monado SLAM Dataset / Odyssey+ (MOO sequences).
  • Repo doc doc/monado/WMR.md is stale: references $bsltdeps and data/monado/, superseded by the VIT-era layout.

Validation evidence (2026-07-05, stationary/headless)

1. Dataset replay through the real Monado→Basalt stack

VIT_SYSTEM_LIBRARY_PATH=…/basalt/build/libbasalt.so \
BASALT_VIT_RERUN=moo09_vit.rrd BASALT_VIT_RERUN_IMU=1 BASALT_VIT_RERUN_IMG_STRIDE=4 \
monado-cli slambatch datasets/MOO09_short_1_updown <config.toml> <outdir>
  • 147/147 frames + 4944/4944 IMU samples consumed; VIO initialized gravity-aligned.
  • tracking.csv: 147 poses; z-range 0 → 0.742 m with x/y within cm — correct for an "updown" sequence.
  • Live-logged .rrd (7.3 MB) passes rerun rrd verify; contents: poses/trajectory (147), stereo images + keypoints (37 each — stride 4), gyro/accel (4944 each), velocity + biases (147), timelines frame 0..146 / sensor_time 0..4.92 s.
  • Beware: slambatch quits on stdin EOF (getchar() exit thread) — keep stdin open, don't < /dev/null.

Native headless viewer screenshot (Rerun 0.33.1, ViewerClient.spawn(headless=True)): 3D trajectory rising vertically with stereo frusta, green feature overlays on the WMR fisheye frames, velocity/IMU/bias plots. Full report: /tmp/rerun-viewer-validation/20260705-moo09/.

2. Headless OpenXR client against the live service

# service (null compositor, euroc device as SLAM-tracked HMD)
XRT_COMPOSITOR_NULL=1 EUROC_HMD=true EUROC_PATH=<dataset> \
VIT_SYSTEM_LIBRARY_PATH=…/libbasalt.so SLAM_CONFIG=<toml> SLAM_SUBMIT_FROM_START=true \
monado-service
# client
XR_RUNTIME_JSON=…/monado/build/openxr_monado-dev.json hello_xr -g Vulkan
  • hello_xr: instance created (RuntimeName=Monado(XRT)), system = Euroc HMD, Vulkan swapchains for both views, session IDLE→READY→SYNCHRONIZED→VISIBLE→FOCUSED, rendered until shutdown; service log error-free with Basalt VIT filter active.
  • Version note: client lib and service must be from the same build, else set IPC_IGNORE_VERSION=1 (git-describe check).

Together these validate every layer except the WMR USB device itself (hardware power blocker) and the physical display path (NVIDIA direct mode).

Runbook: deferred motion + display test (with the headset powered)

  1. Fix headset power (checklist above); confirm with lsusb -d 045e:0659.
  2. Install udev rules (once): 
    sudo cp <rules> /etc/udev/rules.d/70-wmr-headset.rules   # content below
sudo udevadm control --reload && sudo udevadm trigger
    SUBSYSTEM=="usb", ATTRS{idVendor}=="045e", ATTRS{idProduct}=="0659", TAG+="uaccess"
KERNEL=="hidraw*", ATTRS{idVendor}=="045e", ATTRS{idProduct}=="0659", TAG+="uaccess"
SUBSYSTEM=="usb", ATTRS{idVendor}=="03f0", TAG+="uaccess"
KERNEL=="hidraw*", ATTRS{idVendor}=="03f0", TAG+="uaccess"
  3. Start the runtime (WMR auto-detected; drop the euroc/null-compositor test vars): 
    cd ~/0Dev/repos/monado
VIT_SYSTEM_LIBRARY_PATH=$HOME/0Dev/repos/basalt/build/libbasalt.so \
BASALT_VIT_RERUN=spawn XRT_DEBUG_GUI=on \
pixi run ./build/src/xrt/targets/service/monado-service
    (Without SLAM_CONFIG, Monado extracts calibration from the WMR device's factory JSON.)
  4. Watch the live Rerun stream; pick the headset up and translate/rotate it — the trajectory must follow motion without drift explosions.
  5. Run hello_xr (XR_RUNTIME_JSON=$HOME/0Dev/repos/monado/build/openxr_monado-dev.json … hello_xr -g Vulkan); put the headset on — the scene must be stable in space as your head moves. NVIDIA direct-mode/DRM-lease to the headset DP output is the known risk on this box (RTX 3060, driver 595).
